# fit-translator-eval

핏 번역기(S2a) 에이전트의 품질을 자체 평가셋으로 측정하는 스킬. `docs/loop.md`의 Discover/Verify 단계에서 사용.

## When to use

- 에이전트 프롬프트·파이프라인 변경 후 회귀 확인
- 데모 전 품질 게이트 (stop condition 판정)
- 새 공고·경험 샘플 추가 시 기대값 검증

## Inputs

- `eval_set/` — 실제 채용 공고 텍스트 10~20개 + 각 공고용 샘플 경험 덤프 + 수작업 기대 태그
  - 기대 태그 형식: 공고별 `expected_requirements[]` (요구 역량 목록)
- 대상 서비스 엔드포인트 (로컬 또는 배포 URL)

## Procedure

1. 평가셋 각 케이스를 에이전트에 실행 → 출력 수집 (매핑표·재작성 문단·면접 질문).
2. 채점:
   - **요구 추출 재현율** — `expected_requirements` 중 출력 매핑표에 등장한 비율 (문자열 유사 매칭).
   - **근거 없는 판정 수 (P0)** — 매핑표 각 행이 인용한 경험 조각이 입력 경험 덤프에 실존하는지 인간 확인. 없으면 P0.
   - **재작성 문단 사용 가능성** — 인간 평가 3단계(그대로 사용 / 수정 후 사용 / 재작성 필요). "그대로+수정" 비율이 목표 80%.
3. 결과를 표로 출력하고 `NEXT.md`에 요약 추가.

## Output format

```
| case | 추출 재현율 | P0 건수 | 문단 평가 |
|------|-----------|---------|----------|
```

집계: 평균 재현율, 총 P0, 문단 채택률 → stop condition(P0=0, 채택률≥80%) 판정.

## Notes

- 모델·프롬프트 변경은 한 번에 하나만 — 어느 변경이 개선했는지 추적 (`DECISIONS.md` 기록).
- 평가셋은 데모용 공고와 겹치지 않게 관리 — 데모는 별도 unseen 공고로.
