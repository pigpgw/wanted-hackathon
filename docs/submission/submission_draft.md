## 1. 해결하고자 한 문제

> 초안 (문제 정의 필드용):

한국 근로자의 51.8%가 생성형 AI를 업무에 사용하지만, 업무 시간은 평균 3.8%만 줄었습니다. 가장 많이 쓰는 기능은 자료 검색(25%)과 정보 요약(15.4%) — AI는 도입됐지만 업무 방식은 바뀌지 않았습니다. 매일 AI를 쓰는 직장인은 22%에 불과합니다.

원인은 도구가 아니라 구조입니다. 직장인 개인에게는 "내 업무 중 무엇을 자동화할 수 있는지"를 분해·판단할 방법이 없습니다. 자동화 도구(Zapier·Make)는 사용자가 이미 무엇을 자동화할지 알고 있다고 가정하고, 자동화 진단은 기업 단위 컨설팅으로만 팔립니다. 그래서 AI 활용은 검색·요약 같은 표면에 머물고, 매주 반복되는 업무는 그대로 수작업입니다.

이 서비스는 직장인이 자기 업무를 말로 적으면 AI가 업무를 단계로 분해하고, 가장 자동화하기 좋은 단계를 골라, 그 자리에서 샘플 데이터로 실제로 한 번 실행해 결과물을 보여줍니다. "뭘 자동화하면 좋을지 알려주는" 조언이 아니라, 업무 이해 → 우선순위 → 실행까지 가는 개인용 "자기 업무 해킹" 도구입니다.

그리고 실행이 끝이 아닙니다 — AI 결과물을 실무에 쓰려면 회사 양식에 다시 맞추고 숫자를 재검증하는 "재작업"(주 평균 4.5시간)이 남습니다. 이 서비스는 사용자가 우리 팀 양식을 붙여넣으면 그 양식 그대로 결과를 채우고, 결과물 속 수치를 샘플 데이터로 코드가 재계산해 검증 카드로 보여주고, 자연어로 수정을 요청할 수 있습니다. 재작업까지 없애는 게 목표입니다.

(근거: 한국 근로자 AI 사용률·시간 절감 통계 — 아시아경제 2025.8 / 노션×대학내일20대연구소 2026.2 인용, `docs/discovery/problems.md` P1)

## 2. AI 활용 방식 + 결과

> 초안 (AI 활용 방식·결과 필드용):

**활용 방식** — 단순 텍스트 생성이 아니라 3단계 추론 파이프라인으로 LLM을 사용했습니다:

1. **업무 분해**: 비정형 자연어 업무 서술을 구체적 업무 단계로 분해합니다.
2. **자동화 적합도 판정**: 각 단계를 5개 축(반복성·규칙성·디지털 입출력·소요시간·가역성)으로 점수화하고, 실행 가능성을 3종(즉시 실행 / 외부 연동 필요 / 사람 판단 필요)으로 분류합니다. 모든 걸 자동화한다고 하지 않고 불가능한 건 불가능하다고 말하는 게 설계 원칙입니다.
3. **실행**: 사용자가 고른 단계를 업로드한 샘플 데이터로 AI가 실제로 1회 수행해 결과물(정제된 표·보고서 초안 등)을 만들고, 매주 재사용 가능한 프롬프트+SOP 아티팩트를 함께 출력합니다.
4. **재작업 제거 (AI+코드 하이브리드)**: 사용자가 붙여넣은 회사 양식 그대로 결과물을 채우고, 결과물 속 수치를 **코드가 샘플 데이터로 재계산**해 검증 카드로 표시합니다 — LLM 자기 검증이 아니라 결정적 계산이라, 실제로 AI의 오계산을 잡아내 "재계산하면 1,886,000 — 확인 필요"라고 지적합니다. 자연어 수정 지시 → 수정 후 코드가 다시 검증해 "일치"를 확인해줍니다. 워크플로는 URL 링크로 저장돼 다음 주엔 데이터만 바꿔 재실행됩니다.

**결과** —
- 서비스 링크: https://wanted-hackathon.vercel.app/
- 데모: "매주 월요일 매출 데이터 정리해서 보고서 쓴다" → 단계 분해·우선순위 → CSV 업로드 → 보고서 초안 생성 + "수동 40분 → 실행 28초" before/after + 연간 절감 시간 환산 표시. 양식 붙여넣기→그 양식으로 채움, 검증 카드가 수치 불일치 적발→자연어 수정→재검증 "일치"까지 한 화면에서 시연 가능
- 품질 측정: 자체 평가셋 13케이스(일반 8 + 경계 5 — 외부 연동 필요·사람 판단 필요·모호 서술 포함)로 4회 반복 측정. 최종 실행 성공률 **100%**, 치명적 실패(P0) **0건**, 분해 응답 유효율 13/13. 자동 분류일치 10/13 — 나머지 3건은 "보조 실행 단계는 있으나 추천은 human_judgment로 정직"한 논쟁 케이스로, 측정 방법과 함께 `docs/process_log.md`에 기록
- 정직한 분류가 핵심 설계: 채용 결정·ERP 연동·매장 점검 같은 실행 불가 업무를 넣으면 억지로 자동화하지 않고 "연동 필요"/"사람 판단" 배지 + 사유 + 대안 아티팩트로 응답
- 기존 자동화 도구와의 차이: 자연어 서술 → 분해 → **그 자리에서 실행**까지 가는 개인용 서비스는 기존에 없음(추천·분석·컨설팅만 존재 — 대체재 분석 `docs/discovery/problems.md` P1)
- 엔지니어링 차이: 회귀 평가 하네스(`scripts/eval_run.py` + 평가셋 + 4회 iteration 로그)로 프롬프트 변경의 성능 역행을 데이터로 검증 — 추측이 아니라 측정으로 프롬프트를 동결
