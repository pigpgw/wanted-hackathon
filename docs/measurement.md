# Measurement — 지표 계획

대상: A "업무→실행 자동화기" (업무 서술 → 분해 → 우선순위 → 샘플 데이터 1회 실행)

## North Star Metric

**1회 실행으로 절감된 업무 시간** = 수동 처리 예상 시간 − 서비스 실행(+검토) 시간.

- Baseline(수동): 사용자가 서술한 반복 업무를 수동으로 했을 때의 시간 — 사용자 자기보고 or 사전 타이머 측정. 데모 예시 "주간 매출 보고서 정리"는 회당 30~60분 (P1 산정, T3 추정).
- 서비스 목표: 서술 입력→분해→선택→실행 결과물까지 **5분 이내** end-to-end. 실행 자체는 1분 이내.
- 왜 이 지표가 문제 해결을 증명하는가: P1의 장애물은 "뭘 자동화할지 몰라 실행까지 못 가는 단절"이다. 서술→실행 결과물이 실제로 나오고 수동 대비 시간이 줄어든다는 것 자체가 문제 해결의 직접 증거 — 조언이 아니라 **실행된 결과 + 숫자로 된 절감**이 핵심.

## 보조 지표

| 지표 | 의미 | 측정 |
|---|---|---|
| 분해 적절성 | 업무 서술이 실제 단계로 타당하게 쪼개졌는가 | 자체 평가셋(업무 서술 10~20개 + 수작업 기대 단계) 대비 인간 평가 3단계(적절/부분/부적절) — 적절+부분 비율 |
| 자동화 판정 정확도 | "자동화 적합" 판정된 단계가 실제로 실행됐는가 | 적합 판정 단계 중 샘플 실행 성공 비율 (precision) |
| 실행 성공률 | 샘플 데이터 입력 → 결과물 정상 생성 | 전체 실행 시도 중 결과물 생성 완료 비율. **P0 = 실행 실패/빈 결과** |
| 결과물 채택률 | 실행 결과물을 사용자가 다운로드·복사·사용 | 프론트 이벤트 (복사/다운로드 클릭) |
| 검증 카드 정확도 | 코드 재계산이 결과물 수치의 오류를 실제로 적발하는가 | `lib/verify.ts`가 "확인 필요"로 표시한 항목 중 실제 오류 비율 — v2 실측에서 gpt-4o-mini 오계산 2건(1,686,000→정답 1,886,000 / 480,000→정답 482,000)을 정확히 적발 (`docs/process_log.md` 2026-09-19 EVAL·DEPLOY 항목) |

## 데모에서 before/after 보이기

- (좌) 수동: 해당 업무를 수동으로 했을 때의 절차·예상 시간 표시 — (우) 서비스: 분해 맵 → 실행 → 결과물 + 실제 경과 시간 타이머.
- "수동 예상 40분 → 실행 30초"를 숫자로 한 화면에 — North Star를 그대로 시각화.
- 분해 맵의 각 단계에 점수 근거(반복성·규칙성 등)를 표시 — "왜 이 단계인가"를 보여줘서 단순 생성이 아님을 입증 (라이너·셀렉트스타 심사축 정렬).
- 실행 아티팩트(프롬프트팩/SOP)를 함께 출력 — "1회 실행"이 일회성이 아니라 재사용 가능함을 보임.

## 한계 인정

- "실제로 사용자의 반복 업무가 계속 자동화되는가"는 해커톤 기간에 측정 불가 — 데모는 **1회 실행의 실체**를 보이는 것까지. 지속 자동화는 post-launch 계획(실행 아티팩트를 사용자가 자기 환경에 이식)으로 명시.
- 수동 시간 baseline은 사용자 자기보고에 의존 — 데모에서는 사전 측정 1건 + 추정치 범위로 제시.
