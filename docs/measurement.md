# Measurement — 지표 계획

대상: S2a "핏 번역기" (공고 요구 ↔ 경험 매핑 + 맞춤 문단 재작성 에이전트)

## North Star Metric

**공고 1건당 '맞춤 지원서' 완성 시간** — 사용자가 공고를 넣고 "보낼 수 있는" 맞춤 문단 세트를 얻기까지 걸리는 시간.

- Baseline(수동): 공고 분석→경험 매핑→문단 재작성 = 공고당 약 2~5시간 (P2 산정, T3). 현실에서는 이 비용 때문에 같은 이력서를 돌려 씀.
- 서비스 목표: **5분 이내** (입력 1~2분 + 생성 1~2분 + 검토·수정 2분).
- 왜 이 지표가 문제 해결을 증명하는가: P2의 장애물은 "공고별 번역 비용" 그 자체다. 비용이 수 시간 → 수 분으로 떨어지면 같은 이력서 돌려쓰기/지원 포기의 원인이 제거된다. 시간 절감이 곧 문제 해결의 직접 척도.

## 보조 지표

| 지표 | 의미 | 측정 |
|---|---|---|
| 요구 역량 추출 정확도 | 공고에서 뽑은 요구가 실제와 얼마나 맞나 | 자체 평가셋(실제 공고 10~20개 수작업 태깅) 대비 일치율 — 채널코프·셀렉트스타 식 '직접 측정' 어필 |
| 매핑 근거 정확도 | 매핑표의 각 판정(맞음/부분/갭)이 인용한 경험 조각에 근거하는가 | 샘플 결과에 대한 인간 평가, 근거 없는 판정 비율 |
| 재작성 문단 사용률 | 생성 문단 중 사용자가 그대로/약간 수정해 채택한 비율 | 결과 화면의 복사·채택 클릭률 (프론트 이벤트) |
| 사용자당 처리 공고 수 | 맞춤 지원의 총량 증가 | 세션당 공고 입력 횟수 |

## 데모에서 before/after 보이기

- 같은 공고 + 같은 경험 입력 → (좌) 기존 방식: 일반 이력서 문단 (우) 서비스 출력: 매핑표 + 갭 메운 재작성 문단. 나란히 한 화면.
- 타이머: 생성 완료까지의 실제 경과 시간 표시 → "수 시간 → N초"를 숫자로.
- 매핑표의 각 행에 근거(내 경험 조각 인용)를 붙여 "지어내지 않았음"을 보임 — 라이너·셀렉트스타 심사축과 정렬.

## 한계 인정

- "맞춤 지원서가 실제 서류 합격률을 올리는가"는 해커톤 기간에 측정 불가 — 대신 완성 시간·문단 채택률을 프록시로 쓰고, 합격률은 post-launch 측정 계획으로 명시.
