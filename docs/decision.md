# Decision — 최종 선택

## ICE + Judging Fit 점수표

ICE = Impact × Confidence × Ease (각 1~10). 해커톤이므로 Ease 가중 반영해 Ease 3 이하는 탈락 기조. Judging fit = `docs/rules.md` 배점표(기획력·실현가능성·확장성·AI 활용 적절성)와 심사위원 화두 매칭.

## 결론 (한 문장)

**우리는 구직자가 요구 역량이 제각각인 공고에 같은 이력서를 돌려 쓰는 문제(P2)를, 공고 요구 ↔ 경험 조각을 매핑하고 갭을 메우는 문단을 재작성해주는 구직자 측 번역 에이전트(S2a)로 푼다. 데모 scope는 "공고 입력 + 경험 입력 → 매핑표 + 재작성 문단 + 면접 방어 질문" 핵심 플로우 1개.**

## 근거

1. **Judging fit 최상**: 주최사(원티드) 핵심 도메인의 미커버 영역 — 기업용 매칭의 구직자 측 상호보완. 원티드 심사위원이 정확도를 가장 잘 판별할 수 있는 문제 = 좋은 출력이면 가장 높은 점수.
2. **투표 구조 최적**: 예선 온라인 투표 20% — 투표자는 원티드 사용자·구직자일 가능성이 높고, 이 문제는 그들 자신의 문제. 인기상(투표 100%)에도 정렬.
3. **데모 명확성**: 입력 2개 → 출력 3종(매핑표·재작성 문단·면접 질문)이 한 화면에 before/after로 보임. "작동하는 서비스" 심사 기준에 정확히 부합.
4. **AI 활용 적절성**: 요구 추출→경험 조각 검색→매핑 추론→재작성의 다단계 에이전트라 "왜 AI인가"가 자명. 단순 래퍼가 아님을 보이기 쉬움.
5. **확장성 스토리(본선)**: 개인 매핑 → 경험 자산(조각) 누적 → 이직 시장 데이터 — 원티드 생태계와 시너지 서사 가능.

## 트레이드오프 인정

- S1a(업무 해커)가 심사위원 화두 커버리지는 더 넓으나, 2일 내 "실제로 일을 끝내는" 실행 단계 완결성이 불확실. 핵심 플로우를 1회 실행 가능한 자동화로 한정해도 품질 변동이 커 데모 리스크가 있음.
- S2a의 리스크: 원티드가 "이미 한다"고 볼 수 있음 → **"기업용 매칭 ≠ 구직자용 번역"**임을 문제 정의로 명확히 방어. 기존 자소서 AI와의 차별은 '경험 조각 근거 기반 매핑'에 둠.

## 데모 scope (핵심 플로우 1개)

1. 사용자가 채용 공고 텍스트(또는 URL) 붙여넣기
2. 내 경험 덤프(자유 서술) 붙여넣기
3. 에이전트: 요구 역량 추출 → 경험 조각 매핑(맞음/부분/갭+근거 인용) → 갭 메우는 문단 재작성 → 예상 면접 방어 질문
4. 결과를 한 화면에 표시, "같은 이력서" 대비 차이 시각화
