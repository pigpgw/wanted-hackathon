# Service Design — 업무→실행 자동화기

> 설계 제약: **2일 안에 1인이 실제로 만들 수 있는 것만**. 모든 선택은 이 제약 기준.
> 원칙: 넓게 하지 말고, "조언이 아니라 실행"이라는 차별점 1개를 깊게.

## 1. 한 줄 컨셉

직장인이 반복 업무를 말로 적으면, AI가 업무를 단계로 분해하고 가장 자동화하기 좋은 단계를 골라 **그 자리에서 샘플 데이터로 실제로 한 번 실행**해 결과물을 보여주는 서비스.

## 2. 타겟 (좁히기)

- **사용자**: 주간 보고·데이터 정리·문서 취합 같은 반복 업무를 하는 사무직 직장인.
- **첫 버전이 잘 다루는 업무 유형** (데모 보장 범위):
  - 데이터 정리 → 요약·보고서 (CSV/표 → 정제 표 + 보고서 초안)
  - 반복 문서 변환 (회의록 → 액션 아이템, 원문 → 양식 문서)
  - 반복 작성 초안 (정형 답변·보고 초안)
- 범위 밖 업무가 입력돼도 서비스가 정상 동작해야 함 → §7 실행 가능성 분류로 처리.

## 3. 핵심 플로우 (화면 = 단일 페이지 3단계)

```
[1] 서술 입력        →  "매주 월요일 매출 CSV 정리해서 팀장님께 보고서로 올려요"
    (+ 선택: 주 몇 회, 회당 몇 분)

[2] 분해 결과        →  업무 단계 맵 + 단계별 자동화 적합도 점수 + 근거 + 추천 1개
                       사용자가 단계 1개 선택

[3] 실행             →  샘플 파일 업로드(CSV/TSV/TXT/MD) 또는 엑셀 복사·붙여넣기 → 실제 1회 실행
                       → 결과물 미리보기(정제 표/보고서 초안) + 검증 카드 + 자연어 수정
                       → 내보내기: 복사 / .md / 엑셀용 CSV / PDF(인쇄) + 레시피 링크
```

**비개발자 UX 장치** — 첫 방문 **react-joyride 인터랙티브 투어**(8스텝): 보여주기 전용이 아니라 각 스텝의 `before` 훅이 실제 액션을 수행 — 예시 채우기(applyPreset) → 분해(runDecompose) → 추천 단계 선택(selectStep) → 실행(runExecute, 프리셋은 캐시라 즉시). 스텝 타겟은 `data-tour` 속성(description/options/presets/decompose/steps/execute-panel/result), 실행 중 `waiting` 로더 + `targetWaitTimeout` 8s, 타겟 미발견(`error:target_not_found`)·건너뛰기·완료 시 투어 종료+sessionStorage 플래그(세션 1회), 헤더「사용법」버튼 재시작(key remount). 이미 진행된 상태에선 가드로 중복 실행 방지. 토스 블루·20px 라운드 툴팁 커스텀., 실행 중 단계 안내 문구 순환("데이터를 읽는 중…→결과물 작성 중…→재계산 중…"), 결과물 미리보기는 마크다운 렌더링 자체가 프리뷰, 에러 상태에 "예시로 체험" 탈출 버튼.

## 4. 입출력 계약

> **Source of truth**: 이 표 + `lib/types.ts`. 계약을 바꾸면 `types.ts`·이 섹션·`scripts/eval_run.py`·`scripts/ops_check.sh`를 같은 커밋에서 수정.

### 사용자 입력 (UI)
| 필드 | 타입 | 필수 | 비고 |
|---|---|---|---|
| work_description | string | ✅ | 자유 서술, ~1000자 |
| frequency | string | 옵션 | "주 1회" 등 — 점수·절감 계산 보조 |
| manual_minutes | number | 옵션 | 회당 수동 시간 — before/after에 사용. 없으면 AI 추정치 표시(추정임을 명시) |
| sample_file | file | 실행 단계에서 필수 | CSV/TSV/TXT/MD, ≤500KB. 클라이언트에서 텍스트로 읽어 전송 — 서버 저장 없음 |
| sample_paste | text | sample_file 대안 | 직접 붙여넣기 — 엑셀 복사본(탭 구분 TSV)도 그대로 인식. `lib/verify.ts`가 탭·세미콜론·콤마 구분자 자동 감지 |

### API 계약 (types.ts의 interface와 1:1)

`POST /api/decompose` — 입력 `DecomposeInput`:
```json
{ "work_description": "...", "frequency": "주 1회", "manual_minutes": 40 }
```
→ 출력 `DecomposeResult`:
```json
{
  "task_title": "주간 매출 보고서 작성",
  "steps": [
    {
      "id": 1,
      "name": "매출 데이터 수집",
      "score": 2,
      "rationale": "입력이 디지털이나 수집 경로가 외부 시스템 의존",
      "execution_type": "integration_needed"
    }
  ],
  "recommended_step_id": 2,
  "manual_minutes_est": 40
}
```

`POST /api/execute` — 입력 `ExecuteInput` (분해 결과에서 사용자가 고른 step 객체를 통째로 전달):
```json
{
  "step": { "id": 2, "name": "매출 데이터 정리·주간 집계", "score": 5,
            "rationale": "...", "execution_type": "executable" },
  "task_title": "주간 매출 보고서 작성",
  "sample_data": "date,channel,product,amount\n...",
  "sample_filename": "sales_week.csv",
  "output_format": "| 항목 | 값 | 비고 |..."  // 선택 — 사용자 팀 양식. 있으면 그 구조로 채우고 프리셋 캐시 우회
}
```
→ 출력 `ExecuteResult`:
```json
{
  "result_artifact": "정제된 표 + 보고서 초안 (마크다운)",
  "artifact_type": "report|table|draft",
  "execution_seconds": 28,
  "manual_minutes_est": 40,
  "prompt_pack": "매주 재사용 가능한 프롬프트+SOP 텍스트",
  "caveats": ["샘플 100행 기준 실행 — 실데이터는 검토 필요"],
  "cached": true,  // 선택 — 프리셋 사전 실측 결과를 그대로 반환한 경우만
  "verification": {  // 선택 — 검증 카드. 표 데이터(CSV/TSV/세미콜론)면 lib/verify.ts 코드 재계산 결과, 아니면 LLM 생성 카드
    "items": [{"claim": "1,886,000", "basis": "재계산 일치 — amount 전체 합계", "status": "ok"}],
    "summary": "결과물 속 수치 5건을 코드로 재계산 — 5건 일치",
    "source": "code"  // "code" = lib/verify.ts 재계산 / "llm" = AI 검토 — UI 배지로 구분 표기
  }
}
```

`POST /api/revise` — 입력 `ReviseInput` (v2 자연어 수정):
```json
{
  "result_artifact": "현재 결과물 마크다운",
  "instruction": "총 매출을 1,886,000으로 고쳐줘",
  "task_title": "주간 매출 보고서 작성",
  "output_format": "...",  // 선택 — 양식 유지
  "sample_data": "..."     // 선택 — 있으면 수정본에 코드 재계산 재검증
}
```
→ 출력 `ReviseResult`: `{ "result_artifact": "...", "verification": {...} }`

### 결과물 내보내기 (클라이언트 측 — API 계약 아님)

결과물은 화면에서 마크다운으로 렌더링되며, 이 렌더링 자체가 **미리보기**다. 내보내기 4종:

| 버튼 | 형식 | 구현 | 비고 |
|---|---|---|---|
| 복사 | 클립보드 텍스트 | navigator.clipboard | 노션·메일에 붙여넣기용 |
| 엑셀 | `.csv` (UTF-8 BOM) | 결과물의 마크다운 표→CSV 변환, 표별 소제목을 섹션 행으로 | BOM 덕에 엑셀에서 한글 깨짐 없이 바로 열림. **표 없는 결과물이면 버튼 비활성** |
| PDF | 시스템 인쇄 | `window.print()` + `@media print` CSS가 `#print-area`만 출력 | 인쇄 대화상자에서 "PDF로 저장" |
| .md | 마크다운 파일 | Blob 다운로드 | 원본 그대로 |

네이티브 `.xlsx`·`.pptx` 생성은 non-goal (§9) — 라이브러리(xlsx 0.18.x 계열은 알려진 CVE, fflate+수작업 ZIP은 2일 내 검증 리스크) 대신 실제로 열리는 CSV·인쇄 PDF로 사무실 워크플로우의 80%를 커버.

## 5. 실행 엔진 결정: LLM-as-executor

**선택**: 샌드박스·코드 실행 없이, LLM 호출 자체가 "실행"이다. 샘플 데이터를 컨텍스트에 넣고 해당 단계를 실제 수행해 결과물을 출력.

- 왜: 코드 샌드박스(임의 코드 실행)는 2일에 안전하게 못 만든다. LLM 실행은 API 1개로 끝나고, 결과물이 실제 데이터를 변형한 것이라 데모에서 "실행됐다"가 증명된다.
- 대체재와의 차이 유지: Zapier Copilot류는 "구조를 제안"하고 끝 — 우리는 데이터를 넣으면 결과물이 나온다.
- 부가 산출물: 실행과 함께 **재사용 프롬프트팩+SOP**를 출력 → "1회 체험"이 "매주 쓸 자동화"로 이어지는 서사 (지속 자동화는 이 아티팩트를 사용자가 자기 환경에 이식 — post-launch로 명시).

## 6. 자동화 적합도 스코어링 (분해 단계 내부 룰)

단계별 1~5점. LLM이 다음 기준으로 판정(프롬프트에 명시 — how-toai 진단표 룰 차용):
- 반복성: 매일/매주 되풀이되는가
- 규칙성: 판단 기준을 말로 설명 가능한가 (창의적 판단 ↓)
- 디지털 입출력: 입력·출력이 텍스트/표 데이터인가
- 소요 시간: 지금 시간을 꽤 쓰는가
- 되돌릴 수 있음: 틀려도 피해가 작은가 (민감 승인·최종 발송 ↓)

## 7. 실행 가능성 분류 (정직한 경계 — 핵심 설계)

각 단계를 3종으로 분류:

| 분류 | 의미 | 서비스 동작 |
|---|---|---|
| `executable` | 텍스트/표 변환 — 지금 여기서 실행 가능 | 샘플 업로드 → 실제 실행 버튼 |
| `integration_needed` | 외부 시스템 연동 필요 (메일 발송, 사내 DB 수집) | 실행 대신 아티팩트(프롬프트팩/SOP/연동 방법 안내) 출력 |
| `human_judgment` | 사람 판단이 핵심 (협상, 최종 승인) | "자동화 비추천 — 반자동(초안+사람 승인)으로 설계" 안내 |

→ "모든 걸 자동화"가 아니라 **정직한 분해** 자체가 신뢰성 어필(라이너·셀렉트스타 심사축). 실행 불가 입력도 정상 결과가 되게 설계.

## 8. 기술 스택 (확정)

- **Next.js (App Router) 단일 페이지 + API 라우트 4개** (decompose·execute·presets·revise) → Vercel 무료 배포 (심사기간 2주 생존)
- **LLM: OpenAI `gpt-4o-mini`** (프로덕션 확정) — OpenAI 호환 API라 `LLM_BASE_URL`·`LLM_MODEL` env로 다른 모델/엔드포인트 교체 가능. 평가셋 측정은 Gemini로도 수행 (docs/measurement.md)
- 상태 없음: DB·로그인 없음. 파일은 클라이언트 메모리 → API로 텍스트 전송. (예외: `sessionStorage`의 "사용법 봤음" 플래그 — 사용자 데이터 아닌 UI 상태)
- 스타일: Tailwind, 토스 디자인 토큰(#3182F6·flat·큰 여백), 모바일 반응형(sm: 브레이크포인트)
- 환경변수: `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`

## 9. Non-goals (명시적 제외)

- 회원가입·로그인·히스토리 저장
- 실제 외부 서비스 연동 (슬랙·메일·사내 시스템)
- 스케줄링·지속 자동화·멀티 단계 전체 실행 (1개 단계만)
- 코드 샌드박스 실행 (§5로 대체)
- 공유 기능·분석 대시보드
- **네이티브 `.xlsx`·`.pptx` 파일 생성** — 엑셀용 CSV(BOM)·인쇄 PDF로 대체 (§4 내보내기 표). 사유: 의존성 CVE·검증 시간 vs 2일 마감

## 10. 실패 모드 → 처리

| 실패 | 처리 |
|---|---|
| LLM 출력이 스키마 안 맞음 | JSON 검증 + 1회 재시도, 그래도 실패 시 "분해 실패" 상태 표시(조용한 크래시 금지) |
| 실행 결과가 조언으로 끝남 | 프롬프트에 "결과물 자체를 출력, 방법 설명 금지" + 결과가 지시문 형태면 P0로 평가셋에서 검출 |
| 자동화 적합 단계 없는 서술 | 정상 결과: "현재 형태로는 자동화 후보가 없습니다 + 이유 + 반자동 제안" — 실패가 아니라 정직한 분해 |
| 파일 파싱 실패/대용량 | 클라이언트에서 크기·형식 선제 차단, CSV는 앞 N행만 사용 + "샘플 기준" 명시 |
| API 타임아웃/레이트리밋 | 로딩 상태 + 재시도 버튼 + "예시로 체험" 탈출 버튼(프리셋은 캐시라 LLM 장애에도 동작), 데모용 캐시된 프리셋 결과 폴백 1개 준비 |
| 결과물에 표가 없어 엑셀 내보내기 불가 | 엑셀 버튼 비활성 + 툴팁 "내보낼 표가 없습니다" — 조용한 실패 금지 |
| 구분자 오인식 (세미콜론 CSV 등) | `lib/verify.ts`가 탭→세미콜론→콤마 순으로 행 전체 일치 시에만 구분자 인정 — 인식 실패 시 표 검증 대신 자유 텍스트 검증으로 안전 폴백 |

## 11. 데모 시나리오

- **Canonical**: "매주 월요일 매출 CSV 정리해서 팀장님께 보고서로 올려요" + 샘플 sales.csv → 정제 표 + 보고서 초안 + "수동 40분 → 28초"
- **백업 1**: "매일 여러 채널 고객 문의를 표로 정리해요" → 분류 표 + 답변 초안
- **백업 2**: "주간 회의록 정리해서 액션 아이템 공유해요" → 액션 아이템 표
- 프리셋 버튼: 입력창에 "예시로 체험" 버튼 3개 — 심사위원이 실제 입력 안 해도 1클릭으로 전체 플로우 체험 가능 (투표자 전환율에도 유리)

## 12. eval_set 계획 (`scripts/eval_run.py`로 실행·채점)

- 서술 12~15개: 정리·보고·변환 유형 8개 + 경계 케이스(실행 불가 서술, 모호 서술, 비정형 서술) 4~7개
- 각 케이스: 기대 단계 + 기대 자동화 판정 + 샘플 데이터 파일
- stop condition: 실행 성공률 ≥90%, 분해 적절성 ≥80%, "조언으로 끝남" P0 = 0
